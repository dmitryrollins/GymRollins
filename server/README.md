# GymRollins API server

One Cloudflare Worker that replaces Supabase (spec: `docs/specs/2026-11-07-cloudflare-backend-design.md`):

- **Better Auth** at `/api/auth`:
  - Sign in with Apple via the app's id token,
  - bearer session tokens,
  - email and password only when `ALLOW_PASSWORD_AUTH=1`.
- **The app's routes** at `/v1`, all behind the session:
  - `/v1/sync/*` (profile, plan, body weight, workouts, private gyms and listings),
  - the shared gym catalogue: `/v1/gyms`, `/v1/items`, `/v1/listings`,
  - moderation: `/v1/reports`, `/v1/blocks`, `/v1/admin`,
  - gym photos: `/v1/photos`,
  - `DELETE /v1/account`.
- **Public photos** at `/photos/shared/*` and `/photos/exercises/*`, with no session.
- **Claude** at `/mcp`, the MCP server with the 15 tools, behind Better Auth's OAuth (`@better-auth/mcp`):
  - discovery at `/.well-known/oauth-protected-resource/mcp` and `/.well-known/oauth-authorization-server[/api/auth]`,
  - registration (dynamic only), authorize and token at `/api/auth/oauth2/*`; tokens are opaque and checked in D1 on every call,
  - the sign-in page `/connect`, which shows a code the owner approves in the app (`/v1/claude/connect/:code`),
  - `/v1/claude/proposals`, `/v1/claude/last-use` and `/v1/claude/revoke` for the app.
- **D1** holds the data (`migrations/`), and **R2** the photos: `gym-photos`, `gym-photos-private` and
  `exercise-photos`.

Everything runs locally. Nothing here needs a Cloudflare account until the owner approves a deploy.

```bash
npm ci                         # .npmrc sets legacy-peer-deps
npx vitest run                 # tests in workerd against an in-memory D1 (never the dev data)
npx tsc --noEmit
cp .dev.vars.example .dev.vars # then set BETTER_AUTH_SECRET
../scripts/server-up.sh        # http://127.0.0.1:8787 with a local D1 in .wrangler/state
```

Schema:
- `migrations/0001_better_auth.sql` is generated by `npm run gen:auth-schema`.
- `0002_app_schema.sql` is the Postgres schema translated to SQLite.
- The two seeds come from `scripts/gen-exercise-seed.mjs` and `scripts/gen-equipment-seed.mjs` at the repo root. `--check` there catches drift.
- `0005_gyms_photos.sql` adds the catalogue's fold keys and the private caps (triggers).

Exercise photos for the local Worker: `node ../scripts/upload-photos.mjs --target worker` while the server runs.

The iOS integration and UI tests start a Worker of their own (`scripts/test-server.sh`): port 8788, a state folder that
is removed afterwards, and email accounts each test makes fresh (`ALLOW_PASSWORD_AUTH=1` in `.dev.vars`). They never
touch `.wrangler/state` or the Worker on 8787.

The gym suites (`GymSyncIntegrationTests`, `scripts/test-gym-e2e.sh`) make `sync-admin-*@test.local` accounts admins with a
trigger in their throwaway D1.

## Claude

The connection flow:
1. Claude registers itself (`POST /api/auth/oauth2/register`) and sends the browser to authorize.
2. Authorize sends the browser to `/connect`, where the owner signs in. The page shows an approval code.
3. In the app, Settings > Claude > Approve a connection, the owner types the code and approves it. The app shows the client's name and where the page was opened.
4. The browser goes back to Claude, which takes its token. `/mcp` then answers with tools, gated by the Settings toggles.
5. Disconnect Claude in the app revokes every token at once; the next call gets 401.

Claude's browser session (marked `claudeConnect`) and its OAuth tokens are refused on `/v1`, and an app session cannot mint Claude tokens.

Claude locally (no claude.ai). `scripts/server-up.sh` must be running, with `ALLOW_PASSWORD_AUTH=1` in `.dev.vars`:

```bash
node ../scripts/claude-local.mjs smoke              # the whole connection against scripts/server-up.sh
claude mcp add --transport http --scope local gymrollins-local http://127.0.0.1:8787/mcp
node ../scripts/claude-local.mjs approve XXXX-XXXX  # the code /connect shows
```

The manual step for the owner: run the `claude mcp add` line, start `claude`, run `/mcp` and choose gymrollins-local to
authenticate. Open the sign-in URL it prints, sign in on `/connect`, then run the `approve` line with the code the
page shows (or approve it in the app). `last-use` and `revoke` work the same way.

- `migrations/0006_oauth_provider.sql` is generated by `npm run gen:oauth-schema`.
- The MCP code and its tests were copied from `supabase/functions` by `scripts/copy-from-deno.mjs`; plan 30 deletes the originals.
